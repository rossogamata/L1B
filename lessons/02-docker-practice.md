# Заняття 2. Практична робота: контейнери Docker

**Формат:** практичне, 4 аудиторні години. **Максимум:** 20 балів.

## Завдання

Запустити вебзастосунок у контейнері, опублікувати його порт, зберегти файл через том і продемонструвати, що дані залишаються після видалення контейнера. Виконувати роботу в навчальному середовищі, виданому викладачем.

## Обладнання та початкові умови

- Docker Engine і Docker CLI або надане навчальне середовище.
- Загальнодоступний навчальний образ, узгоджений із викладачем (наприклад, `nginx:stable`).
- Доступ до локального порту, вільного для демонстрації.
- Не запускати privileged-контейнери та не монтувати системні каталоги хоста.

## Хід роботи

1. Перевірити версію Docker та наявність образів.
2. Створити named volume з унікальним ім'ям.
3. Запустити HTTP-сервіс із перенаправленням порту хоста на порт контейнера і змонтувати том у каталог, призначений для контенту.
4. Додати в змонтований каталог тестову сторінку або файл.
5. Перевірити відповідь сервісу через браузер або `curl`; показати `docker ps`, `docker logs` та `docker inspect`.
6. Видалити контейнер, запустити новий контейнер із тим самим томом і підтвердити збереження файлу.
7. Зупинити й видалити навчальний контейнер. Том видаляти лише після демонстрації та якщо викладач дозволив.

Приклад команди для орієнтиру (ім'я тому та локальний порт курсант обирає самостійно):

```bash
docker volume create l1b-content
docker run -d --name l1b-web -p 8080:80 \
  -v l1b-content:/usr/share/nginx/html nginx:stable
```

Команда передбачає, що обраний порт вільний. Якщо порт зайнятий, вибрати інший. Не публікувати сервіс у зовнішню мережу.

Додати тестову сторінку можна командою:

```bash
docker exec l1b-web sh -c 'printf "L1B Docker lab\n" > /usr/share/nginx/html/index.html'
```

Для перевірки після повторного запуску створити новий контейнер з тим самим томом і портом, попередньо видаливши старий контейнер. Якщо обраний порт уже зайнятий, замінити його.

## Звіт

Здати короткий Markdown або текстовий звіт:

- команда запуску та пояснення port mapping;
- вивід `docker ps` і перевірки HTTP;
- підтвердження, що файл залишився після заміни контейнера;
- відповіді: чим volume відрізняється від bind mount; що станеться з даними, якщо видалити volume.

Приховати локальні облікові дані та не додавати в звіт секрети чи приватні файли хоста.
